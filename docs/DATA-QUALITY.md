# 练习数据质量：来源、核对方法与结论

练习卷里的每一道题来自 4 本教材 PDF，经 OCR / 文字层提取 → 结构化 JSON →
`scripts/build-data.mjs` 打包进 `data/`（**教材内容受版权保护，`data/` 已被 .gitignore 排除、不随仓库分发**）。
本文记录 2026-11-05 这一轮针对「练习卷填写格式与答案正确性」的核对方法、修正量和遗留风险。

## 1. 数据从哪来（是不是 OCR？）

| 教材 | 原始文件 | 提取方式 | 用途 |
| --- | --- | --- | --- |
| 新概念英语（第一册） | 299 页，**扫描件，无文字层** | macOS Vision OCR → 解析脚本 | 课文、生词、注释、**课文书面练习** |
| 新概念英语语法练习册（第一册） | 580 页，**扫描件，无文字层** | macOS Vision OCR → 解析脚本（正文 15–437、答案 438–579） | **语法练习册的题目 + 答案** |
| 新概念英语 1 课堂笔记&课后练习 | 358 页，**有数字文字层** | PyMuPDF 直接抽文字层 → 解析脚本 | 课堂笔记、**课后作业清单**、课堂跟读 |
| 剑桥初级英语语法（墨菲） | 328 页 | OCR | 语法参考（不进入练习卷） |

因此：**课文书面练习和语法练习册的题目/答案都是 OCR 出来的**，会有识别错误；课堂笔记/作业是 PDF 文字层，基本无 OCR 误差。
此前已做过一轮「双引擎交叉验证」（Vision OCR 建库 + RapidOCR 独立识别比对），
本轮再以**原书页面图**为准做专项复核。

## 2. 本轮核对方法

1. **自动比对**：逐条把 JSON 里的题干/答案与对应页的 OCR 行做归一化 token 匹配，列出覆盖率低、编号错位、截断、乱码的条目。
2. **页面图复核**：对自动标记的条目 + 以往交叉验证的嫌疑条目，逐条打开原书页面图核对；
   必要时用 PyMuPDF 按 200dpi 重渲染放大看。
3. **填写格式专项**：
   - 带空格的填空：书上有一个填空横线，JSON 的 `items[].text` 里就要有对应数量的 `___`（3 个下划线约定）；
   - 改写/问答/抄写题保持完整题干，不截断、不把两题并成一题；
   - 小题编号与答案编号一一对应（示例题通常从第 2 题开始有答案）；
   - 答案块里的「题号-字母」配对表（Match/搭配题）不当作逐题答案（插件端改为配对参考答案 + 自评）。
4. **结构校验**：改完后对 144 课逐课跑插件端的判分引擎测试（题号唯一、每题有输入、答案可解析、填空数量一致、
   全 144 课可构建试卷），并对比 git 版本确认没有误删/误并题组。

## 5. 未消除的风险

- **少量「书上有印刷示例、数据没补录」的题**：段落审核用真实试卷引擎回归发现约 98 道题无参考答案且未被识别为示例
  （26 道带 `___`、72 道纯文本；其中 88 道所在大题其实有答案册）。它们按「无参考答案 / 自评」处理，不影响其他题自动判分；
  清单保存在内部审计存档的 `unrated_questions.json`（不随仓库分发），
  后续可做内容专项或给数据加 item 级 example 标记。

- 两本扫描件的 OCR 仍可能有个别错字/错行；本轮以「有页面证据才改」为原则，改不了的保留并在段报告中标注 needs-human。
- 答案册本身存在题号错位（历史数据里多处），插件端已用「重复字母小题第一处保留答案、后一处自评」和「判对/判错」兜底；
  若遇到可疑答案，以原书页图为准并用手动改判覆盖。
- 配对题、部分无答案册的课文练习只能自评，这是源数据缺口，不是判分 bug。
- 自动校验脚本在插件仓库 `scripts/test-paper.mjs`，数据重建后应重新运行（见 README「开发」）。
